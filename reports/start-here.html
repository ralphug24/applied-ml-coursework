2. Understand one row: inputs and a known answer¶

Each row describes a neighborhood. The 13 features are input measurements, such as average rooms (RM), pupil–teacher ratio (PTRATIO), and property-tax rate (TAX). A target is the answer we want the model to predict: MEDV, the historical median value of owner-occupied homes, measured in thousands of dollars. For example, 24.0 represents $24,000 in the original dataset's historical units.

The training file has 450 examples. We separate inputs (X) from answers (y) so the model cannot read the answer as an input. Locally, this cell uses the repository's data; in Colab, it downloads the same small file from GitHub. The final test file stays unopened until we have chosen a model.

3. Compare three ways to predict¶

  • Mean baseline: predict the average training answer for everyone. This is our reference point: a useful model should do better than a simple guess.
  • Linear regression: learn a weighted combination of the inputs. Training minimizes squared prediction errors.
  • Random Forest: combine 100 decision trees. Each tree learns rules that split the data into groups with smaller squared-error variation; the forest averages their predictions.

Training means learning a model's internal settings from examples. Model selection means deciding which candidate to use. We use 10-fold cross-validation for that decision: divide the 450 rows into ten parts, learn from nine, predict the remaining part, and repeat until every part has been held out. All three candidates use the same divisions. The score averages the ten held-out errors, rather than judging a model on answers it just learned.

We select the model with the lowest mean squared error (MSE). Squaring penalizes large mistakes more strongly. The fixed random seed (42) makes the shuffled divisions and forest more consistent between runs. 100 trees is a model setting; this walkthrough does not search for an optimal tree count.

candidates = {
    "Mean baseline": DummyRegressor(strategy="mean"),
    "Linear regression": LinearRegression(),
    "Random Forest": RandomForestRegressor(n_estimators=100, random_state=42, n_jobs=2),
}
folds = KFold(n_splits=10, shuffle=True, random_state=42)
comparison_rows = []
for name, candidate in candidates.items():
    scores = cross_val_score(candidate, X, y, cv=folds, scoring="neg_mean_squared_error", n_jobs=1)
    # scikit-learn returns negative errors so higher is always better internally.
    # Negate them here to show normal, positive MSE: lower is better.
    comparison_rows.append({"Model": name, "Mean validation MSE": float(-scores.mean())})

comparison = pd.DataFrame(comparison_rows).sort_values("Mean validation MSE").reset_index(drop=True)
display(comparison.round(3))
selected_name = comparison.loc[0, "Model"]
selected_model = candidates[selected_name]
selected_model.fit(X, y)
print(f"Selected {selected_name}, then trained it on all {len(X)} development examples.")

4. Test on examples that did not choose the model¶

Now we open the separate 56-row test file. These answers were not used for training or model selection. This is a final check of how the chosen model behaves on unseen examples from this exercise.

For each row, we pass only the input measurements to predict. We then compare the predicted number with the known answer. Error = prediction − actual: positive means overprediction; negative means underprediction. The target is a neighborhood median, not a prediction for an individual home.

test = read_exercise_file("boston_housing_test.csv")
predictions = selected_model.predict(test.drop(columns="MEDV"))
results = pd.DataFrame({"Actual": test["MEDV"], "Predicted": predictions})
results["Error"] = results["Predicted"] - results["Actual"]
print(f"Final test examples: {len(results)} | All values below use historical $1,000 units.")
display(results.head().round(3))
first = results.iloc[0]
print(f"First example: actual {first.Actual:.2f}, predicted {first.Predicted:.2f}, error {first.Error:+.2f}.")

5. Read the scores and chart¶

MAE (mean absolute error) averages the size of mistakes without their signs. RMSE is the square root of MSE; it also uses the original target units and gives larger errors more influence. For example, RMSE 3.54 is about $3,540 in the dataset's historical units; it is not a guarantee about any one prediction. R² compares the model's squared errors with predicting this test set's mean. 1 is perfect, 0 matches that reference, and negative is possible. R² is not percent accuracy.

On the chart, each dot is a test example. A dot on the dashed line is a perfect prediction. Above it means overprediction; below it means underprediction. Look at the spread, not just the single score.

mse = mean_squared_error(test["MEDV"], predictions)
metrics = pd.DataFrame({
    "Metric": ["MSE (lower is better)", "RMSE (lower is better)", "MAE (lower is better)", "R² (higher is better)"],
    "Test score": [mse, np.sqrt(mse), mean_absolute_error(test["MEDV"], predictions), r2_score(test["MEDV"], predictions)],
})
display(metrics.round(4))
fig, ax = plt.subplots(figsize=(7, 5))
ax.scatter(test["MEDV"], predictions, color="#a77926", alpha=0.8)
low = min(test["MEDV"].min(), predictions.min())
high = max(test["MEDV"].max(), predictions.max())
ax.plot([low, high], [low, high], "--", color="#555555", label="Perfect prediction")
ax.set(xlabel="Known answer (historical $1,000 units)", ylabel="Model prediction (same units)", title=f"{selected_name}: 56 unseen examples")
ax.legend()
fig.tight_layout()
plt.show()

6. What this example establishes—and what to try next¶

You loaded examples, separated inputs from answers, compared a baseline and two models using shared validation folds, trained the selected model, and interpreted its errors on a separate test set. The model learned statistical patterns; the exercise does not establish causation or readiness for deployment. The small historical dataset and its problematic features limit its practical use.

Try one controlled change: change n_estimators=100 to 50 in step 3, then rerun from step 3 onward. This compares a different tree count. Record the cross-validation score and time. Once you start using the test results to choose settings, that test set is no longer an untouched final check; a future reliable evaluation would need new held-out data.
